## 实施顺序与边界

按 T1 至 T9 推进，各项明确列出依赖和验证条件。任务分组不强制等于提交分组；涉及 trait、调用方和序列化的不可分割迁移应形成一个完整、可编译的提交。不得为满足任务顺序留下已知不可编译的中间提交。

本计划不新增完整 GUI、EPUB 打包器或 Session 状态机。集成场景直接调用核心接口并使用内存 writer，证明后续消费者可读取当前文本。

## T1：建立编辑与版本契约

- [x] 定义文档身份、版本、`TextEdit`、`EditBatch` 和可区分的错误类型；明确 UTF-8 字节半开区间。
- [x] 将同批基准坐标、空操作、版本递增、同点插入及边界冲突策略落实到接口与契约测试。
- [x] 为代表性用户场景准备固定输入和预期结果，建立只用于测试的连续 `String` 参考应用函数。

依赖：无。

对应需求：R2、R3。

验证：覆盖空文档、ASCII、中文和 emoji；固定示例必须能区分“同批引用基准文本”与“下一批引用上轮结果”。参考函数独立应用编辑，不能复用待测片段算法。

## T2：实现文档存储与当前文本读取

- [x] 新增文档模块，接管提取结果的正文所有权，保留源编码和路径上下文。
- [x] 实现不可变原文、新增缓冲区和 `Vec<Piece>`；维护 UTF-8 边界、逻辑长度、片段顺序及相邻片段合并不变量。
- [x] 提供借用视图、版本校验的区间分块读取、逻辑行、字符遍历和有限前缀读取。
- [x] 在需要连续文本时仅物化所请求的跨片段行或范围，不提供生产解析路径的隐式全文拼接回退。

依赖：T1。

对应需求：R2、R4、R7。

验证：手工构造不同分片方式下的相同文本，比较所有读取结果；覆盖关键词跨片段、CRLF 跨片段、空行、末尾换行、无末尾换行、跨片段区间与 Unicode 字符计数。检查文档构造通过移动接管原文，而非复制正文。

## T3：实现原子批次应用

- [x] 校验文档身份、基准版本、范围、UTF-8 边界、长度运算和设计中的全部冲突关系，错误保留原始编辑索引。
- [x] 在合法空操作移除后有序扫描片段与编辑，构建候选片段表，接管新增字符串。
- [x] 增加明确提交点；失败或提交前取消不发布候选片段、新增缓冲区或版本。
- [x] 验证空批次不增加版本，其他有效批次只增加一次；包括替换为相同内容的情况。

依赖：T1、T2。

对应需求：R1、R2、R3、R7、R8。

验证：完成 V1、V2、V3、V8；对多轮合法 UTF-8 编辑与 `String` 参考实现比较每一轮结果。非法输入须通过直接构造和反序列化两条路径验证，避免只覆盖构造函数。取消测试使用确定的构建阶段检查点，不用时间竞争断言。

## T4：实现单批位置映射

- [x] 在批次结果中返回旧版本、新版本及旧/新区间对应关系。
- [x] 实现插入点 Before/After、非空编辑边界、外部偏移和内部位置失效语义。
- [x] 在基准视图上校验并创建定位点，映射时校验位置及版本；保留判断编辑是否触及指定范围所需的信息，不保留旧全文或旧片段表。
- [x] 提供连续两批依次映射的验证，不增加通用编辑组合、并发变换或历史日志。

依赖：T3。

对应需求：R2、R5。

验证：完成 V5；包含开头和末尾插入、删除后两端重合、替换内部失效、相邻替换共享边界、长度增加和缩短、跨版本误用。验证“端点可映射”不被用作“解析结果有效”的判定。

## T5：迁移全部现有解析器

- [x] 将三类 parser 的输入和相关辅助函数迁移到当前文本视图，保持原有业务规则。
- [x] 迁移广告过滤：读取含实际行终止符的范围，产生当前版本上的删除编辑。
- [x] 迁移层级 TOC、VBook 所有模式、等分、置信度判断和 `CombinedParser` 的读取路径。
- [x] 迁移元数据前 1000 个 Unicode scalar value 的读取，保留源文件名回退。
- [x] 更新全部受影响的调用方和测试夹具；在同一次完整迁移中保持可编译。

依赖：T2、T3。

对应需求：R1、R4、R8、R9。

验证：完成 V1、V4；既有解析业务测试在未编辑视图上全部通过，再将关键场景放到编辑形成的多片段视图上运行。元数据、广告和标题关键词必须有跨片段匹配案例，等分必须有混合宽度 Unicode 案例。

## T6：接入顺序执行与解析结果有效性

- [x] 提供最小核心入口，按调用方给定顺序运行过滤器，每批提交后下一阶段读取新视图。
- [x] 将 TOC 和自动元数据结果与所属文档版本绑定；安装结果时拒绝过期或跨文档结果。
- [x] 任意实际编辑批次提交后将自动解析结果标记为过期，保留旧结果和已有用户目录调整。
- [x] 提供显式安装当前版本解析结果的路径；自动提取结果不能直接覆盖调用方明确设置的元数据。
- [x] 阶段失败或取消后停止后续阶段，并保留此前已经成功提交的结果。

依赖：T3、T4、T5。

对应需求：R1、R2、R5、R8。

验证：完成 V1、V2、V6、V8。使用能观测调用次数的后续阶段验证失败后没有继续执行；新增标题即使不触及旧标题范围，也必须使旧目录过期。手工调整过的旧目录在过期和重解析后不得被自动覆盖。

## T7：统一预览与区间输出

- [x] 基于同一片段遍历实现版本绑定的范围预览和 writer 输出。
- [x] 为长片段提供取消检查点，正确返回 writer 错误和取消，不承诺外部输出原子性。
- [x] 在消费依赖 TOC 的输出计划时校验其文档版本；使用显式正文范围，不从任意节点 `range` 推断完整章节。
- [x] 构建跨片段和跨输出区间的集成案例，保证不重复重放全局编辑或章节补丁。

依赖：T2、T3、T6。

对应需求：R5、R6、R7、R8。

验证：完成 V7、V8；比较预览字符串、内存 writer 字节和参考实现。模拟中途失败的 writer，验证文档不变并明确部分输出语义。

## T8：收敛旧 API 与更新文档

- [x] 在新调用链完成后移除旧 `TextOp` 编辑入口和未使用的 `TransformOperation` / `ContentRange`；只清理由此次迁移取代的坐标类型。
- [x] 从目录内部与新 wire 格式移除正文字符串 `patch`，更新 serde / specta 及所有相关测试。
- [x] 明确兼容读取：缺失或 `null` 的旧 patch 可接受，字符串或其他非 `null` JSON 值返回不支持旧补丁的错误，不能被未知字段忽略策略吞掉。
- [x] 更新 `DESIGN_NOTE.md`、`TOC_PARSING.md` 和必要 API 文档，说明当前坐标域、版本要求、旧快照与旧补丁的处理。
- [x] 检索确认预览、输出及其他消费者不存在第二套正文补丁执行路径。

依赖：T5、T6、T7。

对应需求：R5、R6、R9。

验证：完成 V9；新快照 round-trip 保留目录结构、标题和定位；旧补丁输入明确报错；无版本的结构快照不能直接认证为当前有效的导出计划。审查 diff，避免夹带节点 ID、树操作或解析配置重构。

- [x] 在本 spec 目录补充 `performance.md` 实测报告；解释不能完成的测量和实际限制，不填入估计性能作为实测结果。
- [x] 根据数据判断是否存在阻碍既定规模使用的问题；树索引、缓冲区回收等后续优化仅在问题有证据时另立任务，不悄悄扩大本期范围。
