# 文本变换流水线：用户需求与故事

- 日期：2026-10-04
- 状态：核心功能已实施；验收证据与工作区既有阻塞见 [performance.md](performance.md)
- 设计：[design.md](design.md)
- 实施与验证：[tasks.md](tasks.md)

## 需求来源与目标

用户已明确确认：过滤、替换后的文本需要继续参与目录识别、后续规则和用户编辑。

当前核心通过 `TextOp` 描述对原文的修改，设计约定在拆分或导出时才物化。这适合独立的原文补丁，但尚未提供后续步骤读取修改结果的统一机制。本 spec 的目标是让整个处理过程围绕当前文本工作，同时保留不可变原文，避免每个阶段复制完整文本。

用户需求约束可观察行为；piece table、批次类型和版本标识等实现选择见设计文档，不将它们作为用户故事本身。

## 范围

包含核心文档读写模型、顺序执行变换、现有解析器适配、解析结果有效性、预览与导出的文本读取接口，以及相关兼容性和验证工作。

不包含完整 GUI 编辑器、完整 EPUB 打包与章节边界推导、Session 状态机重写、输入文件流式解码、撤销历史、协同编辑、任意跨全文正则、历史项目格式迁移和用户目录调整的自动合并。导出接口在此指对调用方已确定的当前文本区间进行读取和输出。

## R1：后续步骤看到前一步结果

**用户故事：** 作为转换电子书的用户，我希望去广告、格式规范化等处理按指定顺序生效，使目录识别和之后的规则基于我实际将要得到的文本。

验收条件：

- **R1.1** 给定“第一回 起点”，先将“回”替换为“章”，再运行仅匹配“第一章”的规则，必须识别到该章节。
- **R1.2** 被前一步删除的广告行不得再参与后续标题、作者、目录或其他规则的匹配。
- **R1.3** 规则顺序由调用方明确指定。同一输入与同一有序规则列表产生相同文本；不得按编辑位置重排不同阶段。
- **R1.4** 每个阶段完成后即可读取该阶段结果，无需先导出或拼接完整文档。

## R2：能够继续编辑新增和替换后的内容

**用户故事：** 作为校订正文的用户，我希望继续修改刚刚插入或替换的文字，而不需要理解这些文字是否存在于最初的文件中。

验收条件：

- **R2.1** 对 `abc` 插入 `xy` 得到 `axybc` 后，能够将新增的 `y` 替换为 `Z`，最终得到 `axZbc`。
- **R2.2** 修改范围可以同时跨过原文片段和新增片段，结果与对当前完整字符串做同样修改一致。
- **R2.3** 同一批编辑均引用该批开始时的文本；下一批引用上一批提交后的文本。前面一项编辑改变长度，不得使同批后面的编辑错位。
- **R2.4** 编辑只允许提交给生成该编辑所依据的文档及版本。过期或来自其他文档的编辑必须被拒绝，不得自动猜测落点。

## R3：无效或冲突编辑不会部分生效

**用户故事：** 作为使用自动规则或外部调用接口的用户，我希望错误规则能够明确失败，而不是悄悄删除错误的文字或只执行一半修改。

验收条件：

- **R3.1** 反向区间、越界区间和落在 UTF-8 编码单元中间的边界必须返回错误，不能依赖字符串切片 panic。
- **R3.2** 同批重叠编辑、同点多次插入以及插入与另一编辑边界的歧义必须按设计中的冲突表拒绝。相邻的非空替换区间允许共存。
- **R3.3** 一个批次任意一项无效时，当前文本、版本、片段和新增缓冲区均保持批次前状态。
- **R3.4** 空批次和只含合法空操作的批次不改变版本；成功提交的其他批次只增加一次版本。
- **R3.5** 错误信息必须能区分版本错误、范围错误和批次冲突，并定位相应编辑项。错误和日志使用英文。

## R4：片段存储不改变解析行为

**用户故事：** 作为配置标题规则和元数据识别的用户，我希望编辑后这些功能继续按照文本内容工作，不受内部如何分段存储的影响。

验收条件：

- **R4.1** 一个标题、广告关键词或元数据字段被分布到多个存储片段后，匹配结果仍与连续文本一致。
- **R4.2** 逻辑行读取正确处理 LF、CRLF、跨片段的 CRLF、空行、末尾换行和无末尾换行；偏移保留实际换行字节长度。
- **R4.3** 现有层级规则、VBook 各模式、等分和元数据规则的业务语义保持不变，输入改为当前文本。置信度判断和正式解析必须读取同一版本。
- **R4.4** 等分继续按 Unicode scalar value 数量平衡，并输出当前文本的 UTF-8 字节范围，不改成按字节数平衡。
- **R4.5** 元数据仍扫描当前文本开头最多 1000 个 Unicode scalar value，并保留源文件名回退行为。

## R5：目录和其他解析结果不会悄悄失效

**用户故事：** 作为检查目录和正文的用户，我希望编辑正文后系统能识别旧目录是否仍可使用，避免标题已经删除、内容已经移动却仍按旧范围处理。

验收条件：

- **R5.1** 目录、自动提取的元数据及其范围必须关联生成它们的文档版本；来自其他文档或过期版本的结果不得作为当前有效结果使用。
- **R5.2** 初版在任意实际编辑批次提交后，将已有自动解析结果标记为过期。重新解析读取最新版本，能够发现新增、删除和改写的标题。
- **R5.3** 旧目录以及用户已做的结构调整不得被静默丢弃或自动覆盖。核心保留旧结果并报告过期；调用方可显式安装在当前版本上重新解析或重新确认的结果。本期不自动合并新旧目录。
- **R5.4** 不受删除影响的定位点可以按明确的左右关联规则迁移；被删除或替换内部的定位点必须报告失效，不得伪装为有效原位置。位置迁移本身不使旧解析结果恢复有效。
- **R5.5** 标题范围、容器聚合范围和完整正文范围不得混为一谈；不能直接将任意目录节点的 `range` 当作完整章节输出范围。

## R6：预览与导出读取同一份结果

**用户故事：** 作为确认转换结果的用户，我希望预览到的正文与导出使用的正文一致，跨章节或跨片段的修改不会漏用或重复应用。

验收条件：

- **R6.1** 对同一文档版本和同一区间，预览拼接的 UTF-8 文本与导出文本读取接口输出的字节完全一致；后续 HTML 转义和模板渲染不在该比较范围内。
- **R6.2** 修改统一应用于文档。预览和导出读取当前结果，不再额外重放全局操作或章节字符串补丁。
- **R6.3** 将当前文本划分为连续、不重叠且完整覆盖的区间并依次输出，结果必须等于整篇当前文本；边界上的新增文字不得重复或丢失。
- **R6.4** 由过期目录生成的输出计划必须被拒绝，直到调用方提供当前版本的有效范围和解析结果。

## R7：保留原文，控制大文本的额外开销

**用户故事：** 作为处理几十到几百 MB 文本的用户，我希望多轮处理不会因为每一轮都复制整本书而迅速耗尽内存，同时原始提取文本保持不变。

验收条件：

- **R7.1** 文档接管提取结果后保留一份解码原文缓冲区，后续阶段不修改它，不按阶段保留完整文本副本。输入文件不被本机制改写。
- **R7.2** 未修改正文通过片段引用复用；额外正文存储来自插入或替换内容。片段索引、批次和临时读取缓冲区需计入内存分析。
- **R7.3** 默认解析和区间输出路径不得为便利而隐式构造完整当前文本。跨片段的逻辑行、元数据前缀和显式请求的预览区间允许局部物化。
- **R7.4** 对稀疏删除、密集替换、多轮编辑分别测量耗时、峰值内存和片段数，并与简单字符串实现对照。报告输入规模、环境和限制，不预设 piece table 一定更快。
- **R7.5** 明确记录新增文本可能接近全文大小、超长单行可能要求大临时缓冲区，以及未回收的新增缓冲区可能随编辑累计；不承诺严格常数额外内存。

## R8：取消和失败具有明确的提交边界

**用户故事：** 作为取消耗时转换的用户，我希望取消后不会继续执行下一步，也不会留下只应用了一部分的编辑批次。

验收条件：

- **R8.1** 解析、候选片段构建、长文本遍历和输出循环检查取消；空输入和空批次在开始处理时也检查取消。
- **R8.2** 提交前观察到取消时，该编辑批次不生效；提交点之后到达的取消不撤回已完整提交的批次。
- **R8.3** 阶段失败或取消后停止后续阶段。此前成功提交的阶段仍然保留，不隐式回滚整条流水线。
- **R8.4** 输出写入失败或取消必须返回错误，不修改文档。外部 writer 可能已有部分输出，完整文件的临时文件发布策略由导出层另行负责。

## R9：核心 API 只有一套正文编辑语义

**用户故事：** 作为 WBook 核心 API 的调用方，我希望自动过滤、用户修订和导出共享同一套编辑规则，避免因入口不同得到不同结果。

验收条件：

- **R9.1** 实施完成后，正文修改统一进入文档批次应用入口。`TextOp`、未使用的 `TransformOperation` 和章节字符串 `patch` 不继续作为三套可独立执行的机制存在。
- **R9.2** 对实际受影响的公开 Rust API、序列化结构和测试给出明确迁移说明。旧的非空字符串补丁不得被静默忽略或当作新格式使用。
- **R9.3** 更新原有设计文档中“全部引用原文、导出才生效”的约定，并明确所有解析范围现在所属的版本和坐标域。

## 完成标准

R1 至 R9 的验收场景均有实现任务与验证路径；现有解析业务测试通过；新增行为与简单字符串参考实现一致；性能报告真实披露成本。完整任务和验收矩阵见 [tasks.md](tasks.md)。
