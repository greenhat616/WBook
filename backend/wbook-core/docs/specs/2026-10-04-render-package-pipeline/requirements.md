## 目标与范围

用户完成正文、目录和元数据编辑后，将当前结果渲染为 HTML 内容，再打包成电子书。首期实现 Tera 渲染、内嵌模板和 EPUB 导出；后处理作为有输入产物依赖的后续阶段设计，MOBI 转换留到后续实施。

本轮先提交 spec，不实施 Rust 功能。本文中的接口、默认值及兼容策略均为拟议契约。

“拆分”解释为按逻辑章节生成多个内容文件；“分页”暂按同一内容文件中请求章前分页解释；“单一 HTML，只改变标题形式”解释为连续正文，仅将章节标题替换为对应层级的标题元素，不请求分页。分页不意味着固定屏幕页数或纸张排版；这一解释已向用户询问，未确认前作为草案假设。

包含章节边界规划、三种布局、文本转义、导航与阅读顺序、EPUB 结构、取消与文件发布。暂不包含可视编辑器、固定版式、按字数再分页、外部模板目录、封面与插图、字体嵌入、MOBI 适配器、发送到 Kindle、通用任务调度器或完整 Session 状态机。

## R1：导出的是用户完成编辑后的结果

**用户故事：** 作为完成校订的用户，我希望导出的正文、目录标题和元数据与本次确认的结果一致。

- **R1.1** 只接受当前文档版本的有效解析结果；缺失、过期和跨文档结果在写入最终文件之前失败。
- **R1.2** 正文读取 `TextView` 当前片段；不重新过滤、不重新解析覆盖用户目录、不重放旧补丁。
- **R1.3** 一个导出作业固定正文版本、目录、合并后的元数据、模板与 options。不能在渲染过程中混入另一轮编辑。
- **R1.4** 目录改名反映到标题与导航；目录顺序决定逻辑章节阅读顺序。首章之前的文本保留在最前面，末章之后的文本不得遗漏。

## R2：三种渲染形式共享内容语义

**用户故事：** 作为选择阅读形式的用户，我希望无需修改正文就能选择分章、章前分页或连续单文件。

- **R2.1** `SplitChapters` 为默认模式，每个有输出内容的逻辑节生成独立 XHTML；纯导航容器不复制子章正文。
- **R2.2** `Paged` 生成一个正文 XHTML，在后续逻辑节开始处请求分页；不在文档开头强制产生空白页。实际分页由阅读器决定。
- **R2.3** `SingleHtml` 生成一个正文 XHTML，不增加强制分页；标题按目录深度呈现。
- **R2.4** 三种模式保留相同的逻辑节、标题和正文顺序，仅文件组织与分页样式不同。单文件模式的目录链接指向同文件内的锚点。
- **R2.5** “单一 HTML”指一个正文内容文件；EPUB 仍可包含独立的导航、样式和包描述文件。首期不增加独立 HTML 下载格式。

## R3：章节范围明确，正文不重复、不丢失

**用户故事：** 作为处理多层目录或等分文本的用户，我希望所有正文恰好出现一次，卷名和章节名也不会被当作正文重复输出。

- **R3.1** 明确区分源标题范围、完整正文块与容器聚合范围；不凭节点是否有子节点、标题内容或 parser 名称猜测。
- **R3.2** 标题式目录按源位置计算各节范围，再按用户目录顺序输出。卷标题与首个子章之间的文字归卷自身，不能在每个子章中重复。
- **R3.3** 已识别源标题由当前目录标题替换，只消耗其明确范围及紧随的一次行结束符；等分产生的正文块不删除首行。
- **R3.4** 无目录的非空文本可导出为一个正文节；空正文明确拒绝。重复标题合法，重复或重叠的源标题范围失败。
- **R3.5** 纯容器、跳级产生的匿名容器、用户调整的目录、CRLF、跨片段标题和无末尾换行都有确定行为。
- **R3.6** 除标题替换与定义的换行排版外，所有源文字均有唯一去向。删除目录项本身不删除正文，内容删除必须通过正文编辑完成。

## R4：开箱即用的 Tera 渲染

**用户故事：** 作为首次导出的用户，我希望无需安装模板即可得到可读电子书，正文中的特殊字符也不会破坏文档。

- **R4.1** 内嵌一套版本化默认模板和 CSS，使用仓库的 Tera 2 依赖，不依赖进程工作目录或外部模板文件。
- **R4.2** 标题、正文、作者及其他文本均作为数据转义；`<script>`、`&`、引号、`{{ ... }}` 保持文字含义，不执行为标记或模板。
- **R4.3** 输出为可解析的 UTF-8 XHTML；XML 禁止字符返回可定位错误，不能静默丢弃内容。
- **R4.4** 预览与打包消费同一份渲染产物。模板渲染只改变输出，不修改当前正文或解析结果。
- **R4.5** 默认路径不将整本正文或整本 HTML 放入一个 Tera context；长单行等局部内存成本必须记录。

## R5：首期导出 EPUB

**用户故事：** 作为电子书读者，我希望导出文件可被 EPUB 阅读器打开，目录跳转和阅读顺序正确。

- **R5.1** 输出可重排 EPUB 3，包含合法 OCF 容器、包元数据、manifest、spine、导航、正文与 CSS；ZIP 成功不等于 EPUB 合格。
- **R5.2** 标题、语言、唯一标识及修改时间必须有效；作者可缺省。用户显式元数据优先于自动解析，不猜测正文语言。
- **R5.3** 导航保留有名节点的层级与顺序，所有链接和锚点能解析到实际产物；匿名容器不显示空目录项。
- **R5.4** EPUB 打包不依赖 Kindle 软件；已有 `epub-builder` 优先复用，是否满足契约由验证决定。
- **R5.5** 三种模式均通过结构检查和 EPUBCheck 验证，并记录阅读器人工检查结果及分页差异。

## R6：后续格式能声明产物与工具依赖

**用户故事：** 作为以后需要 MOBI 的用户，我希望系统先准备 EPUB，再使用可用转换工具生成 MOBI，依赖缺失时给出明确说明。

- **R6.1** 渲染产物、打包产物与转换产物分开表达；未来 MOBI 路径为 `RenderedBook → EPUB → MOBI`，不能把全部格式当作互不依赖的打包器。
- **R6.2** 首期仅公开 EPUB 目标；请求未知或未支持格式明确失败，不生成扩展名伪装的文件。
- **R6.3** 后续转换器声明输入格式、输出格式及外部工具要求。调用前检查依赖；只执行目标必需步骤，不为 EPUB 探测或启动 Kindle 工具。
- **R6.4** 多个目标共用同一个作业内的 EPUB 前置产物；依赖失败时下游不运行，失败信息区分缺工具、转换失败和取消。
- **R6.5** 本期只落实分层边界和 EPUB 路径，不实现通用 DAG、任意 shell hook 或虚假的 MOBI 成功分支。

## R7：取消和失败不损坏既有输出

**用户故事：** 作为取消导出或重试失败任务的用户，我希望原始文档与已有电子书保持完整。

- **R7.1** 规划、渲染、打包和发布前检查取消；失败或取消停止后续步骤，并返回阶段与具体上下文，错误和日志使用英文。
- **R7.2** 中间文件与未完成 EPUB 保存在本作业临时位置；全部必要验证通过后才发布最终文件。
- **R7.3** 首期目标已存在即失败，不覆盖。发布操作本身必须保证不覆盖，不能仅依赖先检查文件存在与否。
- **R7.4** 发布前失败或取消清理本作业临时文件，保留其他作业与已有目标。发布成功后到达的取消不撤销已发布结果。
- **R7.5** 后续转换失败不改变其输入 EPUB；只有明确请求的成功产物才可发布。中间 EPUB 与用户请求的 EPUB 具有不同生命周期。

## 完成标准

R1–R7 均在设计中有确定契约和实施任务；本轮以文档链接、现有接口依据、需求到验收的覆盖检查为完成标准。功能实施阶段则必须提交测试、EPUBCheck 与阅读器验证证据，不能将草案描述为已实现。
