# Session 管线：需求与验收条件

- 日期：2026-10-04
- 状态：草案；本目录描述待实施行为，不代表已有能力
- 设计：[总览](design.md)、[Workspace 层](design-workspace.md)、[Session 运行时层](design-session.md)
- 实施与验证：[tasks.md](tasks.md)

## 目标与当前事实

本阶段把已有提取、文本处理、解析与 EPUB 导出接入可创建、观察、取消和关闭的 Session。Workspace 表示一份可编辑电子书工作区及其全部领域状态；Session 是 Workspace 在进程内的一次打开；一次解析或导出是 Session 上的一个操作。操作完成不等于 Session 关闭。

当前 `Session` 只有状态与元数据，`SessionHandle`、`Command` 和 `SessionError` 为空，`SessionManager` 只有容器，`Wbook` 尚未持有 Manager。已有 `ProcessingDocument` 和 export 模块可以独立调用，但没有 Session 运行时。2026-10-04 分析时执行 `cargo test -p wbook-core --lib --locked --offline`，140 个核心测试通过；它们不构成 Session 生命周期的验收证据。

## 本阶段范围

包含 Workspace 领域 API、Session 运行时（单操作准入、取消、完成凭据、快照、panic 隔离、关闭）、Manager 注册与 shutdown，以及 `Wbook` 对这些能力的封装。

仅使用已有 SimpleExtractor、广告过滤器、TOC 配置和元数据解析器。不扩展处理算法或输出格式，不增加插件注册框架、自动重试、撤销系统、协同编辑或通用 DAG 调度。

本期不实现 GUI、Tauri 命令、HTTP/WebSocket 传输协议、应用窗口退出事件接线或百分比进度条。核心必须提供后续适配所需的快照、结果和可等待 shutdown 接口，不能据此宣称桌面应用已完成接入。

本期也不实现 Session 间的全局并发配额、预览资源的传输层访问和导出复用预览；设计中保留了它们的扩展点。

**Session 持久化保存、自动保存、重启恢复及崩溃恢复明确为 TODO，不在本阶段实现或验收；但 R8 的持久化就绪约束本期必须满足。** 进程退出后 Session 不恢复；运行期类型的序列化不构成项目保存格式。

## R1：创建、隔离与访问

**用户故事：** 作为调用方，我希望打开多个文件并独立处理，其中一个文件失败不会损坏其他文件。

- **R1.1** 创建成功返回进程内不复用的 SessionId 与 Handle，工作区获得 WorkspaceId；创建不读取文件。源路径与处理配置随创建固定。
- **R1.2** 创建时验证配置，错误配置不注册 Session。输入不存在或读取失败作为 initialize 失败返回，Session 仍可查询、再次 initialize 或关闭。
- **R1.3** Manager 提供创建、查询、列举、关闭与 shutdown；不暴露 Workspace、注册表或文档引用。
- **R1.4** 同一个 Session 最多有一个已接受且未结束的操作，冲突时明确返回 Busy，不排队。多个 Session 可以并行。
- **R1.5** Workspace 以移动所有权交给工作线程，不为每次操作或通知复制全文。快照不包含全文或整棵目录。

## R2：初始化与续跑

**用户故事：** 作为处理文件的用户，我希望初始化按顺序执行，失败后可以知道哪些修改已经生效并继续。

- **R2.1** initialize 依次执行提取、接管正文、按序过滤、解析、安装；只有安装成功才报告初始化成功。
- **R2.2** 空过滤器列表合法；过滤器顺序与 TOC 配置由调用方在创建时指定，不自动挑选或重复套用过滤器。
- **R2.3** 失败或取消后停止后续步骤，保留已提交的接管与过滤，快照报告过滤进度；未提交的当前批次不生效。
- **R2.4** 首次安装结果之前可以再次调用 initialize，从已提交的进度继续，已完成的过滤器不再执行；安装过结果之后 initialize 返回 AlreadyInitialized。
- **R2.5** 过滤未完成时，调用方可以直接对当前文本解析并安装；这是显式选择，此后剩余过滤器不会再自动执行。不实现通用 Retry。
- **R2.6** 从源文件重新创建会重新读取当时的文件，不承诺它与上次提取内容一致，也不丢弃仍打开的旧 Session。

## R3：编辑、重解析与版本保护

**用户故事：** 作为校订者，我希望正文、目录和元数据修改可以继续参与预览和导出，而过期操作不会覆盖新修改。

- **R3.1** 写操作携带 expected Revision，不匹配时返回 StaleRevision 且不改变任何状态。正文编辑仍使用现有 EditBatch 和 DocumentVersion 校验；错误版本、错误范围或冲突批次不改变文档。
- **R3.2** 正文发生实际修改后，已安装的目录和自动元数据标为过期并保留；预览渲染和导出拒绝过期结果。
- **R3.3** parse 只返回解析结果，不改变工作区；只有 install 才替换已安装结果。parse 不得覆盖手工目录或 overrides。
- **R3.4** install 接受解析结果或调用方修改过的目录与元数据，经既有结构反序列化和范围校验后整体替换；跨文档、旧版本或越界的结果被拒绝。不把 NodeId 当作跨安装的稳定身份。
- **R3.5** 每次持久状态提交后 Revision 递增：接管正文、每个过滤器完成、安装、正文实际修改、overrides 变化。空编辑与相同 overrides 不递增；读取、解析、预览和导出不递增。
- **R3.6** overrides 独立于自动元数据；移除某个 override 后恢复使用自动值。

## R4：预览与导出可重复使用

**用户故事：** 作为确认电子书结果的用户，我希望导出之后继续修改，并能确认预览和导出的来源。

- **R4.1** 支持有界正文读取（单次不超过 1 MiB UTF-8 字节）、已安装结果读取和 render_preview。正文读取校验 DocumentVersion；渲染要求已安装结果有效。
- **R4.2** 一个工作区最多保留一个预览；任何提交都使其失效并关闭。以相同 ExportOptions 重复请求时返回现有预览，不重新渲染；渲染失败保留旧预览。
- **R4.3** 预览以目录和文件清单返回，只在下一次提交、被替换或 Session 关闭之前有效，不作为传输层的长期句柄。
- **R4.4** export_epub 基于当前已安装结果独立渲染和打包，不读取也不替换预览。
- **R4.5** 导出成功返回产物路径、DocumentVersion、Revision 与实际标识；成功、失败或取消都不自动关闭 Session，之后可以继续编辑和导出。
- **R4.6** 沿用"不覆盖既有目标"策略。EPUB 已发布后到达的取消不撤销文件，也不把成功改报为取消。清理失败作为告警保留，不将成功发布改报为导出失败。

## R5：取消与提交结果

**用户故事：** 作为取消长任务的用户，我希望取消可以及时传到后台，并知道最终哪些结果已经提交。

- **R5.1** Cancel 指定 OperationId；不会因旧请求延迟到达而取消新操作。重复取消同一活动操作幂等，无匹配操作时返回 NotActive。
- **R5.2** 取消、查询、订阅和关闭不经过工作线程，不被正在执行的数据操作阻塞。
- **R5.3** 每次操作使用新的取消令牌。接受取消请求不等于操作已经取消，必须等待操作的实际终态。
- **R5.4** 在各阶段交界检查取消，包括提取返回后、接管正文前。不可中断的文件读取、解码和库调用允许延迟响应；本期不承诺固定取消时限或强杀线程。
- **R5.5** 每个提交点之前的取消不生效于该提交，之后的取消不回滚该提交。操作结果携带结束时的 Revision，调用方据此知道已提交的前缀。
- **R5.6** 每个已接受操作恰好完成一次；正常错误、取消、panic 和关闭竞争都不能留下永远 Running 的状态。

## R6：关闭与应用级停止

**用户故事：** 作为关闭文档或退出的调用方，我希望后台处理确实结束，且自己的输出文件不会被清理掉。

- **R6.1** Close 原子地禁止新操作，取消活动操作，等待工作线程实际返回，再关闭工作区并释放文档。重复或并发 Close 得到同一个关闭结果；调用方放弃等待不中止关闭。
- **R6.2** 只有操作已经结束且清理已经尝试后才发布 Closed；清理失败记录路径和英文原因，不伪装为全部清理成功。
- **R6.3** 关闭只清理工作区持有的临时资源，不删除已发布 EPUB 或输入文件。关闭过程中完成的发布，其操作结果仍报告成功产物。
- **R6.4** Manager 在关闭完成后移除 Session；已获取的 Handle 仍可读取终态和关闭结果，不能再执行数据操作。新的 Manager 查询返回 NotFound。
- **R6.5** Shutdown 先禁止创建，再同时请求所有 Session 关闭，等待全部结束并汇总结果。并发创建与 shutdown 之间不允许遗漏已接受的 Session。
- **R6.6** Drop 只尽力发出停止请求；只有显式 await shutdown 能提供已结束保证。运行时提前销毁、进程强杀和机器断电不在有序关闭保证内。

## R7：异常隔离和可观察性

**用户故事：** 作为 GUI 或 CLI 的接入方，我希望区分输入问题、忙碌、取消和后台异常，并在重新订阅后知道当前状态。

- **R7.1** 快照分别表达生命周期、活动操作（阶段、是否请求取消）、工作区状态（文档状态、Revision、DocumentVersion、过滤进度、预览）及最近一次操作摘要。
- **R7.2** 订阅先获得当前快照，然后获得更新；更新有单调递增序号。允许合并中间快照，不能依赖订阅收到每个阶段或每个操作结果。
- **R7.3** 每个已接受操作返回可等待的独立完成凭据；后续操作不能覆盖该凭据的结果。调用方放弃等待不会隐式取消操作。
- **R7.4** 入口拒绝（Busy、Unavailable、Closing、Closed、NotFound、ShuttingDown、InvalidConfig）同步返回，执行失败在操作结果中返回。执行错误保留 Extractor、Document、Parser、Export 的类别与英文消息，不把底层错误压成一个字符串或空枚举。
- **R7.5** 工作线程可捕获的 unwind panic 使该工作区进入 Lost：拒绝数据操作，但允许查询和关闭；其他 Session 继续工作。panic 的操作副作用视为未知，不虚构回滚或成功。
- **R7.6** 不把内存时间线当作持久审计日志；只保留当前快照与最近一次操作摘要，通过 tracing 记录状态转换，不累积全文、目录或操作历史。

## R8：持久化就绪（本期约束，不是功能）

**用户故事：** 作为后续实现保存与恢复的开发者，我希望不必重新设计 Session 分层就能加入持久化。

- **R8.1** Workspace 是唯一的持久化对象。Session、操作、快照、令牌以及除 WorkspaceId 外的各种 ID 都是进程内资源。
- **R8.2** 持久状态集中在 WorkspaceState，只包含拥有所有权、且有或可以有序列化表示的数据；处理配置以 FilterConfig / TocParserConfig 形式保存，不保存 trait object。
- **R8.3** 持久状态只在提交点变化，每次提交 Revision 递增；WorkspaceId 与 Revision 以后随保存持久化，Revision 跨保存与恢复保持单调。
- **R8.4** 预览、清理告警与操作结果不属于持久状态。
- **R8.5** Manager 以 open(Workspace) 为基本入口，以后的恢复不改变运行时接口。
- **R8.6** 本期不定义保存格式，不提供 save/load 或占位接口，不创建数据目录或数据库。

## 完成标准

R1–R8 有实现与自动化验收；核心端到端示例完全通过 Wbook / SessionHandle 完成创建、初始化、编辑、重解析、预览、导出和关闭，不直接绕过 Session 调用流水线。测试、取消限制和实际检查结果记录在实施时新增的 verification.md；未实施前不勾选任务或声称完成。
