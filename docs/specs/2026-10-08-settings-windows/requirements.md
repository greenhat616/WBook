# 设置多窗口：需求

- 日期：2026-10-08
- 状态：已实施并验证
- 设计：[design.md](design.md)；任务：[tasks.md](tasks.md)；证据：[verification.md](verification.md)

## 背景

全局设置（`/settings`）与本书设置（`/sessions/$sessionId/settings`）目前都在当前窗口内切换路由打开。会话窗口进入全局设置后只能经 App Bar 回到首页，回不到原会话；设置与工作区也无法并排查看。

## R1：全局设置窗口（桌面）

- App Bar 的设置按钮在桌面端打开独立的全局设置窗口，不再改变当前窗口的路由。
- 全局设置窗口全局唯一：已打开时只聚焦，不新建。
- 窗口按现有约定先隐藏、前端渲染后显示；关闭窗口只关闭窗口本身，不影响任何 Session。

## R2：本书设置窗口（桌面）

- 工作区的“本书设置”入口在桌面端打开该 Session 专属的设置窗口；每个 Session 至多一个，已打开时只聚焦。
- Session 关闭（含关闭其工作区窗口）时，对应的本书设置窗口随之销毁。
- 关闭本书设置窗口不关闭 Session。

## R3：设置在窗口间同步

- 全局设置保存后，所有正在显示全局设置的窗口 / 标签页更新为新值，无需手动刷新。
- 本书设置保存后（无论来自设置窗口还是工作区“解析规则”面板），同一 Session 的其他视图更新为新值。
- 表单没有未保存修改时，直接载入新值；有未保存修改时保留用户输入，提示“设置已在其他窗口更新”，并提供“载入最新”（放弃本地修改）。
- 并发保存不得静默覆盖：基于过期版本的保存被拒绝并提示，表单保留。
- 同步对桌面与浏览器模式行为一致，不依赖平台特定的浏览器存储共享。

## R4：浏览器模式

- 浏览器模式仍使用页内路由打开两个设置页，保留“关闭设置”返回按钮；多个标签页之间按 R3 同步。

## 范围边界

- 不做关闭设置窗口时的未保存修改确认（与当前路由离开时的行为一致）。
- 不调整会话窗口 App Bar 的首页链接（另行处理）。
- 不改变设置的数据模型、持久化格式与校验规则。

## 验收

- core：全局设置带 revision；过期 revision 的保存被拒绝且不落盘；订阅者收到初始值与每次成功保存后的新值。
- tauri：设置窗口唯一性、Session 关闭时销毁本书设置窗口、关闭设置窗口不关闭 Session、设置窗口标签不会被识别为 Session 窗口；全局设置订阅流经 HTTP 测试覆盖。
- 前端：干净表单随外部更新刷新；脏表单保留输入并提示；过期保存显示冲突；桌面端入口调用打开窗口命令，浏览器端仍走路由。
- 真实本机流程：桌面端同时打开工作区、本书设置与全局设置窗口，跨窗口保存后其他窗口即时更新。
